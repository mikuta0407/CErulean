CErulean wasm 計測（段階2・段階5）

tools/web-build.sh で wasm をビルドし、tools/serve-bench.py で配信して http://localhost:8000/rust/web/www/bench/ を開く（キャッシュを無効にして配信する）。

条件を選んでから WM5 のイメージ（PPC_USA.bin）を選ぶと、リセットから走らせて速度と基準との 一致を測る（数十秒〜数分。イメージはこのページの外に送らない）。同じイメージでもう一度測るときは 「同じイメージでもう一度」を押す（条件ごとに新しい Worker で走らせる）。

メモリ（JIT で増える分は V8 等の最適化コンパイルの一時的な作業領域）はブラウザの道具で見る: Chrome はタスクマネージャ（Shift+Esc）の「メモリ使用量」の最大、Firefox は about:processes、 Mac の Safari はアクティビティモニタの「Safari Web コンテンツ」（このページのプロセス）。 iPhone は数値を見にくいので、タブが落ちて再読み込みされないかを見る。

「JIT の経過診断」は、1 つの Worker で JIT なし → JIT のホストだけ（コンパイルしない）→ JIT ありを順にリセットから 3 億命令ずつ走らせ、2500 万命令ごとの速度と素の JS の速さを出す （シナリオ・JIT の選択は使わない。Safari で JIT ありが遅い原因の切り分け。Safari を完全に 終了して開き直した直後に行う）。

JS・小さな wasm・エミュレータ本体の速さを比べ、遅い原因を切り分ける。
