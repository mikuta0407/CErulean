# ROM イメージを書き換える場合の方針（RAM・本体ストレージ）

2026-09-30 時点の整理（未着手）。今の方針は「ROM は書き換えない（装置を用意するだけ）」で、
本体ストレージの永続化は無改変のイメージでは成り立たないと分かった（docs/storage-persistence.md）。
この文書は、書き換えを認める場合に何をどの順で行うかをまとめる。実装する前にユーザーと決めること。

## 原則

1. **配布しない・ロード時に当てる**: 改変したイメージは作らない・配らない。ユーザーが用意した
   無改変のイメージを読み込んだ後、エミュレータがメモリ上で当てる（今の OEMAddressTable 相当の
   ロード時変換と同じ位置づけ）。
2. **既知のイメージだけ**: イメージの SHA-256 ごとの当て方の表（アドレス・元のバイト列・新しい
   バイト列）を持ち、元のバイト列が一致しなければ当てずにエラーにする（USA・JPN で番地が違う。
   モジュールの位置は USA と JPN でずれていた）。
3. **既定はオフ・構成として記録**: 既定の構成（基準シナリオ）は今のまま。当てたかどうか
   （当て方の版）はスナップショットに入れ、イメージ ID と合わせて照合する（決定論のため）。
4. **根拠を残す**: 当てる箇所ごとに、逆アセンブル（`cerulean disasm`）で読んだ根拠を
   コメントとこの文書に残す（「推測で埋めない」は同じ）。
5. **当てやすいところだけ**: カーネル・OAL（VA 0x8007xxxx〜0x800Bxxxx）は BIN のレコードに
   **圧縮されずに** 入っており、直接読める・当てられる（OEMInit の文字列・コードをイメージから
   読めた）。ROM の DLL（XIP モジュール）は圧縮フラグ付きで、展開・再圧縮が要るので避ける。
   レジストリの既定値（default.hv 等）も圧縮されているので、当てずに実行時の操作で変える。

## A. RAM を増やす

現状: SDRAM 128MB（PA 0x30000000〜0x37FFFFFF）。OEMAddressTable は VA 0x80000000→PA 0x30000000
（64MB）と 0x94000000→PA 0x34000000（**192MB**）を持ち、OEMGetExtensionDRAM が PA 0x34000000〜 を
書き込みでプローブして「found 0x04000000 bytes」（64MB）を見つけ、先頭 32MB を RAMFMD に予約し、
残り 32MB をシステムに返す。

1. **まず書き換えなしで試す**: S3C2410 は SDRAM のバンクが 2 つ（バンク6 = 0x30000000・
   バンク7 = 0x38000000、各 128MB まで）なので、バンク7 にも RAM を置いて合計 256MB にし、
   OEMGetExtensionDRAM がどこまで見つけるかを観察する（アドレス表の範囲では最大 192MB）。
   以前「64MB＋折り返し」で誤検出したので、折り返さない RAM として置く。
2. 見つける量に上限（プローブのループの回数・定数）があれば、その定数だけを当てる。
3. 代償: スナップショットは RAM を無圧縮で持つので 256MB になる（ブラウザ版は gzip で保存）。
   ブラウザの wasm のメモリも増える（計画書 §6.2 の予算を見直す）。基準は構成を変えたときだけ
   変わる。

## B. 本体ストレージ（RAMFMD）の容量を増やす

- RAMFMD の大きさは OEMGetExtensionDRAM の予約の定数（「reserving 0x02000000 bytes」）で決まる
  と見られる。RAMFMD の見出しにはセクタ数（0x1F81 × 0x1000 バイト）が書かれる。
- 手順: (1) RAMFMD（ramfmd.dll）が大きさをどこから得るか（OAL の IOCTL か、予約の結果か）を
  トレースで確かめる。(2) OAL の予約の定数を当てる（A で増やした RAM の中で、例えば 96MB）。
  ramfmd.dll 側に決め打ちがあれば、それは圧縮された DLL なので別の方法を考える。
- システムに返す RAM とのかね合い（プログラムのメモリが減る）を決める。

## C. 本体ストレージを再起動・イメージからの起動で残す

原因（docs/storage-persistence.md）: OEMGetExtensionDRAM のプローブ（0x800AFA68）が毎回
PA 0x34000000 の先頭に 55555555h・AAAAAAAAh を書き、RAMFMD の署名 "FLSH" を壊す。

1. **当てる箇所**: プローブで壊す先頭の 1 ワードを、書く前に読んで書き戻す（あるいは、
   起動引数 PA 0x3002004E の bit0＝ソフトリセットの印が立っていればプローブを飛ばす）。
   当てた後、RAMFMD の 2 つ目の署名の検査（ramfmd.dll 0x01665448〜。場所は見出しから計算）も
   通ることを確かめる。
2. **エミュレータ側**:
   - 「ソフトリセット」の操作: RAM を残して CPU と周辺機器だけをリセットし、印（+0x4E の bit0）を
     立てて起動し直す。
   - 「本体ストレージのイメージ」: RAMFMD の 32MB（または B で増やした分）をファイル（ブラウザは
     OPFS）に保存し、イメージから起動するときに RAMFMD の領域に置いて印を立てる。
     カードのイメージと同じく入力・構成として扱い、スナップショットにも入る。
3. 期待: RAMFMD にある本体のファイルシステム（My Documents 等。WM5 のレジストリが本体の
   ファイルシステムに置かれるなら設定も）が残る。どこまで残るか（レジストリ・インストールした
   アプリ）は当てた後に観察で確かめる。
4. 注意: 起動の途中で壊れた状態（書き込み中の電源断に当たる）を作らないよう、保存は命令境界の
   スナップショットと同じ扱いにする。

## D. 採らない方針

- **NOR フラッシュ（amdnord.dll）**: ドライバは Am29LV800BB（1MB）の ID を求めつつ 64KB × 510
  ブロックと決め打ちし、消去の番地は 16MB で折り返す。実在の構成と合わず、DLL は圧縮されていて
  当てにくい。C の RAMFMD の方が当てる箇所が少なく、DE の構成（RAMFMD）にも沿う。
- **圧縮された DLL・レジストリのハイブを当てること**: 展開・再圧縮の仕組みを作ることになり、
  範囲が大きい。レジストリの既定値（例: ネットワークカードの接続先）は実行時の操作か、C で
  残った設定で足りる。

## 進める順（提案）

1. A-1（書き換えなしで RAM 256MB を試す）。ここまでは原則に反しない。
2. C（永続化）: 当てる箇所が 1 か所で効果が大きい。ロード時に当てる仕組み（原則 1〜4）を
   ここで作る。
3. B（容量）: A・C の結果を見て、RAMFMD の大きさの決まり方を確かめてから。
